# TokenPeek 发布规则与已踩过的坑

> 给接手发布的人 / AI。按这份文档执行，可以避免 1.6 → 1.8 期间踩过的全部问题。

## 1. 一句话流程

```
改代码 → swiftc 编译 + --self-test → ./package.sh（自动升版本，arm64）→ ./package-intel13.sh（Intel）
→ git commit + push main → 打 tag → gh release create（只传 4 个 macOS 包）
→ site/publish.sh 更新 releases.js → 手改站点版本文案 → 部署 gh-pages → 线上验证
```

## 2. 版本号规则

- 位置：`Info.plist` 的 `CFBundleShortVersionString`（如 `1.8`）和 `CFBundleVersion`（Build，如 `9`）
- `package.sh` 每次运行会**自动 +1**：`1.8 → 1.9`，Build `9 → 10`
- 只想重打同一版：`SKIP_VERSION_BUMP=1 ./package.sh`
- **必须是 `主版本.次版本` 两段纯数字**。不要写成 `1.6.01`：
  - 更新检查按点分段转 Int 比较，`1.6.01` 会被当成 `1.6.1`，能用但不是预期
  - `package.sh` 的自动加版会把 `6.01` 判为非法次版本并归零，下一版直接算成 `1.0`
- 本机手动改过版本号（例如曾把本机 App 标成 `1.6.01`）时，注意它和仓库 / Release 的版本号不是一回事，不能拿版本来判断二进制是否一致

## 3. 打包

```bash
cd "/Users/xa/Documents/Default Project/DeepSeekCost"

# 1) 编译检查（只写 /tmp，不影响仓库）
swiftc -sdk /Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk \
  -swift-version 5 -target arm64-apple-macosx14.0 main.swift -o /tmp/check

# 2) 自检
/tmp/check --self-test

# 3) Apple Silicon 包（会升版本 + 写入 Info.plist，产物在 dist/，同时复制到桌面）
./package.sh

# 4) Intel 包（沿用 Info.plist 里的版本，必须在 package.sh 之后跑）
./package-intel13.sh
```

产物：

```
dist/TokenPeek-<版本>-AppleSilicon.dmg/.zip
dist/TokenPeek-<版本>-Intel.dmg/.zip
```

规则：

- `dist/`、`build/`、`site/downloads/` 都在 `.gitignore`，不要提交
- 构建脚本依赖 `MacOSX26.5.sdk` 回退（本机只有 CommandLineTools），不要删这段逻辑
- 安装说明文件从仓库上一级读取：`../分享说明.txt`、`../分享说明-Intel13.txt`
- Intel 包会额外把 `LSMinimumSystemVersion` 改成 `13.0`
- 签名是 ad-hoc，不做 Apple 公证

## 4. Release 规则

- 标题：`TokenPeek <版本>`，例如 `TokenPeek 1.8`
- tag：`v<版本>`，必须指向要发布的那个提交；用 `--verify-tag` 防止打错
- 资产：**只传 4 个 macOS 包**（AppleSilicon + Intel 的 dmg / zip）
- **不上传 Windows 包、不在任何文案里提 Windows**
- 文件名保持 ASCII：`TokenPeek-1.8-AppleSilicon.dmg`，不要用中文或空格
- 正文模板：

```markdown
- 条目 1
- 条目 2

下载：
- Apple Silicon（macOS 14+）：TokenPeek-1.8-AppleSilicon.dmg / .zip
- Intel（macOS 13+）：TokenPeek-1.8-Intel.dmg / .zip

安装包为 ad-hoc 签名，未做 Apple 公证；首次打开请右键 App → 打开。
```

命令：

```bash
git push origin main
git tag -f v1.8
git push -f origin v1.8

gh release create v1.8 \
  dist/TokenPeek-1.8-AppleSilicon.dmg \
  dist/TokenPeek-1.8-AppleSilicon.zip \
  dist/TokenPeek-1.8-Intel.dmg \
  dist/TokenPeek-1.8-Intel.zip \
  --title "TokenPeek 1.8" \
  --notes-file /tmp/notes.md \
  --latest --verify-tag
```

## 5. 官网发布规则

### 5.1 数据文件

```bash
cd site
./publish.sh --version 1.8 --mac-version 1.8 \
  --base "https://github.com/0xTack/TokenPeek/releases/download/v1.8/" \
  --notes "条目 1|条目 2"
```

- `--notes` 用 `|` 分隔，条目里**不能出现 `|`**
- `--base` 必须指向 GitHub Release 对应版本目录，不要用 `downloads/`（Pages 单文件 100 MB 上限）
- 脚本只更新 `assets/releases.js`（版本、下载列表、更新日志历史）
- `publish.mjs` 目前只生成 macOS 条目；不要再加回 Windows

### 5.2 必须手动改的文案（脚本不会动）

| 文件 | 位置 | 示例 |
|---|---|---|
| `site/index.html` | 页头胶囊 | `已适配 DeepSeek · macOS 1.8 已发布` |
| `site/index.html` | 下载区说明句 | `当前版本 macOS 1.8。…` |
| `site/index.html` | 页脚 | `<span class="footer-version">macOS 1.8</span>` |
| `site/macos-open.html` | 校验命令里的文件名 | `TokenPeek-1.8-AppleSilicon.dmg` |

每次发版后检查 `site/` 下是否还有旧版本号：

```bash
grep -rn "1\.7\|1\.6" site/*.html site/assets/releases.js | head
```

### 5.3 部署 gh-pages

```bash
rm -rf /tmp/tp-pages
git clone --branch gh-pages --single-branch --depth 1 \
  https://github.com/0xTack/TokenPeek.git /tmp/tp-pages

rsync -a --delete \
  --exclude ".git" --exclude "downloads/" --exclude ".DS_Store" \
  site/ /tmp/tp-pages/

cd /tmp/tp-pages
git status -s          # 先看差异，确认没覆盖别人的改动
git add -A
git commit -m "Release TokenPeek 1.8"
git push origin gh-pages
```

规则：

- **不要部署 `downloads/`**（体积大，Pages 放不下；安装包都在 Release）
- 每次 clone 最新的 gh-pages，不要复用旧目录
- `git status` 里如果出现你没改过的文件，先查清来源再提交（可能来自另一个会话）
- `tools/mock-win.html` 不再部署，clone 后如存在先删掉

## 7. 发布问题清单

### 7.1 自动加版把版本算错（`1.6.01` → `1.0`）

- 症状：跑完 `package.sh`，版本变成 `1.0`
- 原因：`CFBundleShortVersionString` 写成三段且次版本带前导零，`package.sh` 的纯数字判断失败，次版本归零
- 处理：把 `Info.plist` 改回两段纯数字，再跑 `package.sh`；以后不要用 `x.y.0z` 形式

### 7.2 重复打包又升了一版

- 症状：只想重打同一版，结果版本又 +1
- 处理：用 `SKIP_VERSION_BUMP=1 ./package.sh`

### 7.3 更新日志里混进「下载：」等说明

- 症状：`publish.sh --notes-file` 把整个文件内容当条目，更新日志出现下载说明
- 处理：只把纯条目写在 notes 文件里；或者直接用 `--notes "条目1|条目2"`

### 7.4 站点版本号没更新

- 症状：`releases.js` 已是新版本，页面还显示旧版本
- 原因：`publish.sh` 只改 `releases.js`，页头 / 下载区 / 页脚 / 打开说明是手写的
- 处理：按 5.2 的表格逐处修改，然后全站 grep 旧版本号

### 7.5 gh-pages 覆盖了别人的改动

- 症状：部署后另一个会话刚发的站点内容消失
- 原因：`rsync --delete` 用本地 `site/` 覆盖远端
- 处理：部署前先 clone 最新 gh-pages，`git status` 看差异；本地 `site/` 要先包含对方已提交的改动（或先 `git pull` 仓库）

### 7.6 本地 `origin/gh-pages` 是旧引用

- 症状：`git log origin/gh-pages` 显示的提交和线上不一致
- 原因：本地的远程分支引用不会自动更新
- 处理：`git fetch origin gh-pages`，或用 `git ls-remote origin gh-pages` 看真实值

### 7.7 一个仓库两个会话同时改

- 症状：`git push` 时提示非快进，或提交历史里出现意料之外的提交
- 处理：提交前先 `git status` / `git log --oneline -5`；不要 `push -f` 主分支（tag 例外）；发现别人的提交不要回滚，保留并一起部署

### 7.8 本机 App 和线上版本号相同、内容不同

- 场景：发布后又在本机改代码，用 `./build.sh` 安装，版本号没变
- 风险：误以为线上已经包含修复
- 处理：以提交 / tag / Release 为准；本机验证版要么记下编译时间，要么临时把 Build 号 +1，发布时再统一

### 7.9 面板 / 弹窗类改动无法自动验证

- 现象：后台启动的 App 无法通过脚本拉起状态栏 `NSPopover`（激活被系统拦住），截图验证不了
- 处理：只能本机手动验证；在交接文档里写清「已验证 / 未验证」

### 7.10 Windows 相关内容残留

- 已处理：Release 不再传 Windows 包、`publish.mjs` 不再生成 Windows 条目、站点当前文案无 Windows
- 仍存在：历史更新日志里 1.3 的两条提到 Windows；仓库 `windows/` 源码和工具还在
- 规则：**以后不再提及 Windows、不再发布 Windows 包**

### 7.11 打 tag 打错提交

- 现象：`v1.5` 曾指向旧提交，需要重打
- 处理：`git tag -f v1.8 <commit>` 后 `git push -f origin v1.8`；Release 用 `--verify-tag` 确认 tag 已存在

### 7.12 安装包下载 404

- 原因：`--base` 版本目录写错、tag 没推、资产名和 `releases.js` 记录不一致
- 处理：先 `gh release view v1.8` 看资产名，再对 `site/assets/releases.js` 里的 `file` 字段；必要时用 `./publish.sh --check` 校验 sha256

### 7.13 首次打开被 Gatekeeper 拦

- 原因：ad-hoc 签名、无公证
- 处理：文档 / 页面统一写「右键 App → 打开」；不要承诺双击即开

## 8. 硬约束（不要改）

- Bundle ID：`local.deepseekcost`
- 数据目录：`~/Library/Application Support/DeepSeekCost`
- 可执行文件名：`DeepSeekCost`
- 官网部署分支：`gh-pages`
- 更新检查仓库：`0xTack/TokenPeek`
- 不再提及 / 发布 Windows
- 打赏页不接支付回调
- 本机只有 CommandLineTools，`MacOSX26.5.sdk` 回退逻辑必须保留
